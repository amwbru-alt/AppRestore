# Ошибки входа на сайте

`/health` проверяет процесс, а `/v3/status` — лишь часть таблиц. Их успешный
ответ не доказывает готовность таблиц сессий, рефералов и заказов.
Проверьте БД из каталога `server/node` на сервере с его существующим `.env`:

```bash
npm ci
npm run doctor
```

Команда только читает структуру таблиц, не меняет пользователей, пароли или
балансы. Если выведено `database_schema_outdated`, примените схемы:

```bash
npm run migrate
npm run doctor
```

Миграции создают недостающие таблицы и сохраняют существующие записи.
Если проверка сообщает об отсутствующем столбце уже существующей таблицы,
`CREATE TABLE IF NOT EXISTS` не изменит её автоматически: потребуется сверить
её структуру с SQL соответствующей версии. Не удаляйте таблицы для исправления.
После успешной проверки перезапустите существующий процесс Node тем же
менеджером процессов, которым он был запущен, и обновите страницу браузера.

Сайт теперь различает ошибки схемы, подключения и конфигурации БД. Неожиданный
сбой получает номер ошибки: он отображается пользователю и записывается в stderr
Node в строке `request_failed`. Лог содержит только номер и категорию, без SQL,
паролей, почты, токенов, кодов и тела запроса. По номеру можно найти событие в
журнале вашего менеджера процессов. Сам номер не раскрывает сведения аккаунта.
Регистрация и вход отдельно сообщают, если они уже выполнены, но последующая
загрузка кабинета не удалась. Повторная регистрация для этого не нужна;
кнопка «Проверить подключение» повторяет загрузку кабинета без повторной оплаты.
