# Банки: одно название, разные приложения

Откройте **«Восстановить из истории» → «Мои банки»** после входа в Apple ID.
Программа сопоставляет точные App Store ID из загруженной истории со списком
вариантов банка. Пользователь видит название банка и название именно того
приложения, которое найдено в его истории. Чужие варианты из каталога не
показываются и установкой не перебираются.

Если найдено несколько ранее полученных вариантов, они отображаются отдельно:
пользователь выбирает нужный. История покупок не позволяет надёжно определить,
какое приложение было установлено на конкретном телефоне последним. Автоматически
подменять один ID другим или устанавливать все варианты программа не будет.

«Вся история» сохраняет доступ к остальным приложениям этого Apple ID. Ввод
произвольного ID в этой вкладке скрыт. Попытка вызвать восстановление ID, которого
нет в истории текущего аккаунта, также блокируется в обработчике действия.
Проверка наличия в истории не гарантирует, что Apple ещё разрешает загрузку.

## Обновление сервера

Из корня Git-клона:

```bash
git switch codex/apprevive-icons
git pull --ff-only
mysql --host=shuloquaticu.beget.app --port=3306 --user=apple --password --database=apple < server/promo/catalog-schema.sql
mysql --host=shuloquaticu.beget.app --port=3306 --user=apple --password --database=apple < server/promo/catalog-groups-schema.sql
cd server/node
npm ci --ignore-scripts
cp -n catalog-groups.json catalog-groups.local.json
node --env-file=.env src/manage.mjs import-groups catalog-groups.local.json
sudo systemctl restart apprevive-api
```

Если API запускался вручную, остановите прежний процесс и выполните `npm start`.
Кредиты, промокоды, заказы и партнёрские привязки не затрагиваются.
После обновления сервера пересоберите Mac и Windows:

```bash
gh workflow run gui-build.yml --repo amwbru-alt/AppRestore --ref codex/apprevive-icons
```

## Где указывать названия банков и ID

Файл на сервере: **`server/node/catalog-groups.local.json`**. Это локальная копия
[стартового файла](server/node/catalog-groups.json), исключённая из Git, чтобы
`git pull` не конфликтовал с вашими настройками.

Структура (пример нужно дополнить своими вариантами):

```json
[
  {
    "id": "t-bank",
    "name": "Т-Банк",
    "iconUrl": "",
    "apps": [
      {"trackId": "455652438", "name": "Тинькофф (Оригинал)"},
      {"trackId": "6476151601", "name": "Т-Банк (T-Start)"}
    ]
  }
]
```

- `id` — постоянный ключ группы: латинские строчные буквы, цифры и дефис.
- `name` — общее название банка в интерфейсе.
- `iconUrl` — необязательная HTTPS-картинка банка.
- `apps` — список вариантов с точными App Store ID. `name` служит запасной
  подписью; при наличии названия в истории используется название из истории.
- Можно задать отдельный `iconUrl` у варианта.

Один App Store ID может принадлежать только одной группе. Дубликаты и неверные
ID отклоняются до изменения базы. Стартовый файл группирует **37 ID** Т-Банка,
Сбербанка и Альфа-Банка из уже имеющегося каталога проекта. Это группировка
существующих записей, а не подтверждение, что каждый вариант сейчас загружается.
Бизнес-приложения и инвестиционные приложения не смешаны с основными банками.

Отредактируйте файл и примените:

```bash
cd /opt/apprevive/server/node
nano catalog-groups.local.json
node --env-file=.env src/manage.mjs import-groups catalog-groups.local.json
```

Замените путь на свой каталог репозитория. Импорт **целиком заменяет состав
групп** одной транзакцией: сохраняйте в файле все нужные группы. Отсутствующие
группы отключаются; убранные ID теряют групповую привязку. Операции с другими
таблицами не выполняются. После успешного импорта перезапустите настольное
приложение, чтобы оно обновило каталог. Повторная сборка для изменения состава
групп не требуется. На сайте варианты также сворачиваются в одну карточку банка.

## Как работает проверка

1. ipatool читает историю текущего Apple ID. Загрузка идёт фоново, страницы
   истории обновляют список по мере получения.
2. API отдаёт метаданные: ID, название варианта и его группу.
3. AppRevive на компьютере находит пересечение этих ID с историей аккаунта.
   Совпадение по одному названию банка владельцем не делает.
4. Кнопка восстановления передаёт точный найденный ID. Перед запуском обработчик
   снова проверяет, что он находится в истории текущего Apple ID.
5. Если нужный вариант не найден, установка не запускается. Перебора загрузок,
   попыток получить новый вариант и списаний за невыбранные варианты нет.

История покупок и пароль Apple ID нашему API для сопоставления не передаются.
Список вариантов скрыт **в интерфейсе**, но технические ID не являются секретами:
они входят в публичные метаданные каталога. Пользователь видит только совпавшие
варианты своего аккаунта, а не весь список альтернатив.

При ошибке чтения истории, неполной загрузке или когда Apple не возвращает старые
записи отсутствие совпадения означает «не найдено в загруженной истории», а не
«никогда не было на аккаунте». Переключение Apple ID использует уже существующий
раздельный кеш истории. Получение приложения на аккаунт также не доказывает,
что оно было установлено на текущем устройстве. Статус удаления из App Store
этот фильтр не проверяет: он проверяет наличие ID в истории.

## Таблицы

`apprevive_catalog_groups` — ключ, название, HTTPS-иконка и флаг группы.
`apprevive_catalog_variants` — однозначная связь App Store ID с группой.
Названия и картинки вариантов остаются в `apprevive_app_catalog`. Импорт
обновляет эти метаданные и включает перечисленные варианты в каталог.
На старом сервере без новых таблиц `/v1/catalog` продолжает отдавать плоский
каталог; для полноценных групп нужны импорт и новый клиент.
