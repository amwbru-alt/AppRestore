# Автоматическое пополнение каталога AppRevive

После успешной загрузки истории текущего Apple ID и проверки подключённого
телефона программа отправляет метаданные отсутствующих приложений на
`POST /v3/catalog/discover`. Нужны точные числовой App Store ID и bundle ID;
совпадение по названию, поиск похожего приложения и случайный вариант банка
не используются для определения ID.

Передаются только `trackId`, `bundleId`, `name`, `source`. Apple ID, почта,
пароли, токены, UDID, дата покупки и весь список установленных приложений в
запрос не включаются. ID нельзя получить достоверно для каждого удалённого
приложения: записи с неизвестным ID или bundle ID не отправляются.

Новая таблица `apprevive_catalog_discoveries` содержит поля:

- `store_id` — уникальный App Store ID;
- `bundle_id`, `name` — заявленные клиентом метаданные;
- `source` — заявленный источник, не независимое доказательство;
- `state` — `pending`, `approved` или `rejected`;
- `created_at`, `reviewed_at` — даты получения и проверки кандидата.

Повторные отправки не создают дубликаты и не меняют название, привязку bundle ID
или решение администратора. Если ID уже есть в основном каталоге, включая
отключённые записи, новая заявка не создаётся. При сетевой ошибке восстановление
продолжается независимо от этой отправки, а следующая успешная проверка повторяет
неподтверждённую отправку. За один проход передаются до 200 новых для процесса
ID партиями до 50. Остальные могут быть отправлены при следующем обновлении.

Клиентские данные нельзя считать достоверными только потому, что запрос пришёл
от программы. Поэтому в общий каталог ID попадает после проверки администратором:
откройте сайт → Администрирование → Найденные приложения. Проверьте ID, bundle ID,
название, при необходимости добавьте HTTPS-адрес иконки и нажмите «Опубликовать».
Ненужные или неподтверждённые записи отклоняются. Утверждение кандидата не
перезаписывает уже существующее приложение. Решение записывается в журнал
администратора. Каталог не служит доказательством, что приложение было у другого
пользователя: фильтрация по его истории и телефону продолжает действовать.

## Обновление сервера

Из корня существующего проекта:

```bash
git pull origin codex/apprevive-icons
cd server/node
npm ci
npm run migrate
npm run doctor
```

Миграция добавляет таблицу, не удаляя текущие данные. Используется существующий
серверный `.env`. После успешной проверки перезапустите процесс Node своим
менеджером процессов. Файл схемы: `server/promo/discoveries-schema.sql`.
Нативные клиенты получают отправку ID после установки новой сборки Mac/Windows.
Старые клиенты и выдача уже купленных кодов сохраняют прежние контракты.
