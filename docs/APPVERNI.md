# АппВерни — исходное приложение для Mac и Windows

Все пользовательские функции находятся в **нативном приложении Qt** на базе
исходного AppRestore: вход/регистрация сервиса, Apple ID с паролем и 2FA,
каталог, установка и администрирование. Браузер, веб-сервер, второй Терминал
и отдельный worker для этого режима не нужны.

## Обновление и запуск на вашем Mac

Если раньше был открыт сайт: остановите его в Терминале сочетанием Ctrl+C.
В папке клонированного проекта выполните:

```bash
git pull --ff-only
bash start-macos.sh
```

Рабочая ветка изменений: `codex/appverni-service` (историческое имя ветки).
При новом скачивании:

```bash
git clone --branch codex/appverni-service https://github.com/amwbru-alt/AppRestore.git AppVerni-desktop
cd AppVerni-desktop
bash start-macos.sh
```

Нужен Python 3.12, установленный отдельно от системного Python 3.9.
Скрипт также умеет выбирать установленный Python 3.10, 3.11 или 3.13;
для этого проекта на Mac предпочтителен 3.12. Скрипт создаёт собственное
окружение `.venv-appverni`, не меняет чужой `.venv`, устанавливает зависимости,
собирает ipatool с патчами проекта и открывает приложение. При первом запуске
потребуются интернет и время на подготовку. Повторный запуск использует
проверенные компоненты, если их версии и исходники не изменились.

Для сборки ipatool нужны инструменты разработчика Apple. Если их нет,
скрипт открывает штатное окно установки Command Line Tools. Завершите
установку в этом окне и снова выполните `bash start-macos.sh` в том же
Терминале. Go ставится локально скриптом bootstrap с проверкой закрепленного
SHA-256, системный Go не заменяется.

Автоматическая macOS-сборка в этой среде не запускалась; интерфейс и логика
проверены на Linux с PySide6. Для Intel Mac остается ограничение исходного
`requirements/runtime.lock`: не все закрепленные колеса доступны. MacBook
Air на Apple Silicon использует вариант macOS arm64.

## Вход в сервис

Первое окно — отдельная нативная форма входа АппВерни. Кнопка
«Зарегистрироваться» открывает отдельную форму регистрации.

Если база пустая, приложение явно предлагает **«Создать владельца
приложения»**: этот первый локальный аккаунт становится администратором.
Повторная первичная настройка блокируется атомарно. При существующей базе
новые регистрации дают только пользовательскую роль; администратор
автоматически не назначается.

Если раньше запускался локальный сайт и в `data/appverni.sqlite3` уже есть
аккаунт, каталог и заказы, приложение использует эту базу. Можно войти с
прежними данными; повторная регистрация не нужна. Когда такой базы нет,
данные размещаются в пользовательском каталоге AppRestore. Для явного выбора
перед запуском задайте `APPVERNI_DATABASE` — абсолютный путь к SQLite.
Два desktop-окна с одной базой одновременно не запускаются (QLockFile).

Пароль сервиса — минимум 12 символов, хранится как scrypt-хеш с солью.
Пароль Apple ID здесь не используется. «Аккаунт сервиса» позволяет выйти
и открыть форму входа другого пользователя. Заказы и история разделены
по ID пользователя; административные действия повторно проверяют роль
в базе, а не только видимость кнопки.

## Вход Apple ID и двухфакторная аутентификация

1. В приложении откройте **«Apple ID»** или нажмите «Войти в Apple ID»
   в каталоге.
2. Введите настоящий email Apple ID и его пароль.
3. Нажмите «Войти». Когда Apple потребует 2FA, появится поле кода — введите
   код с доверенного устройства и нажмите «Отправить код».
4. При необходимости приложение отдельно спросит пароль локальной связки
   ipatool. Это не пароль Apple ID. Он остается в памяти до закрытия окна
   и передается дочернему процессу через защищённый stdin/PTY.

Используется исходный `AppleLogin`/PTY/ConPTY-код приложения, без веб-форм
и без передачи пароля в аргументах процесса. При уже открытой действующей
сессии Apple может не запросить пароль и 2FA повторно. Форма регистрации
АппВерни сессией Apple не является.

После успешного входа приложение автоматически запускает проверку всей
истории Apple ID. Сначала определяется email из настоящей сессии ipatool;
подставленная пользователем почта не считается проверкой. Полный список
сохраняется в SQLite. При последующих открытиях каталога используется
сохраненный результат для этого пользователя и Apple ID. Кнопка
«Проверить историю Apple ID» делает явное обновление. Частичные результаты,
обрыв сети и ошибки Apple не стирают прошлый успешный снимок.

Приложения, полученные на Apple ID, в том числе бесплатные, считаются
найденными в истории. Это не подтверждение даты физической установки
на iPhone и не гарантия доступности файла у Apple.

## Каталог и установка

Подключите iPhone по USB, разблокируйте, подтвердите «Доверять» и выберите
устройство в штатном интерфейсе. В разделе **«Установить»** находятся
карточки с фото, названием, App Store ID и результатом проверки Apple ID.
До проверки и для отсутствующих в истории приложений кнопка установки
отключена.

При нажатии передаётся ID карточки. Приложение получает сохраненный
App Store ID и передает его исходному движку AppRestore. Скачанный IPA
проверяется исходными механизмами; успех заказа записывается только после
подтверждения установки на выбранном iPhone.

Первая успешная установка на аккаунт АппВерни — в подарок. Резерв атомарный:
повторные клики, разные Apple ID и конкурентные обращения не дают несколько
бесплатных установок. Далее — **100 ₽ за установку**.

Платный заказ имеет статус «Ожидает оплаты» и не выполняется. Платежный шлюз
и списания оставлены на следующий этап. При сбое до установки подарок
сохраняется; при неизвестном результате после обращения к iPhone —
резерв сохраняется до проверки устройства. Приложение не закрывается
обычным способом во время выполняемой операции; после аварийного завершения
свои незавершенные установки переводит в «Проверьте iPhone», без автоматического
повтора. Задачи старого внешнего worker при этом не меняются.

В новой оболочке старые кнопки установки ведут в каталог с учетом тарифа.
Исходные Apple ID, обзор телефона, диагностика и настройки сохранены.
Явные developer-режимы `--ui quick`, `--ui quick-legacy`, демо и исходный CLI
сохранены для совместимости; они не являются защищенным платежным клиентом.
Открытый исходный движок не превращен в DRM.

## Администрирование внутри приложения

Раздел **«Администрирование»** виден владельцу и администраторам:

- «Приложения»: создать/выбрать карточку, название, App Store ID, описание,
  выбрать локальное PNG/JPEG до 2 МБ и включить/выключить показ в каталоге.
  Фото проверяется Qt, сохраняется как PNG до 512×512 рядом с базой.
- App Store ID существующей карточки не меняется: другой ID — новая карточка.
  Скрытие карточки не удаляет историю установок.
- «Пользователи»: зарегистрированные аккаунты и роли.
- «Заказы»: стоимость, статус и результат. Для неопределенного результата
  оператор проверяет iPhone и нажимает «Подтвердить результат после проверки
  iPhone», указывает результат и основание. Произвольное подтверждение оплаты
  не добавлено.

Резервируйте SQLite вместе с соседней папкой `images`. Локальные базы,
соли/хеши паролей, пользовательские фото, IPA и окружения не включаются в Git.

## Что относится к будущему серверному этапу

Сейчас учетные записи, каталог, история и тариф используют **локальную базу
этого экземпляра сервиса**. Это не готовая централизованная учетная система
для всех компьютеров клиентов: для нее нужно отдельно развернуть backend,
подключить API-клиент, серверную проверку полномочий и платежный провайдер.
Регистрация на одном Mac автоматически не появляется на другом.

Предыдущие `appverni serve` и внешние worker-модули оставлены как отдельный
прототип серверной части и для совместимости базы. Обычный запуск desktop
их не вызывает. Для пользовательского сценария используйте приложение.

## Если ipatool не найден

Запускайте `bash start-macos.sh`: он готовит сборку с патчами и кладет её
в `bin/ipatool`. Программа ищет его там первой. Не скачивайте случайный
бинарник вместо сборки проекта. Для своего проверенного расположения можно
задать `APPRESTORE_IPATOOL_PATH` полным путем. Это путь к исполняемому файлу,
а не к папке. Отсутствие компонента отображается в окне входа.

## Ручной запуск в уже подготовленном окружении

```bash
source .venv-appverni/bin/activate
python -m apprestore_gui.app
```

По умолчанию открывается нативная оболочка с аккаунтами сервиса и каталогом.
Для выбора старой базы явно также доступно:

```bash
python -m appverni --database data/appverni.sqlite3 desktop
```

Windows: подготовьте Python 3.12, драйвер Apple, зависимости по
[RUN-FROM-SOURCE.md](RUN-FROM-SOURCE.md), patched ipatool в `bin/ipatool.exe`
и запускайте `python -m apprestore_gui.app` в том же окружении.

## Проверки

```bash
python -m pytest -q tests/test_desktop_service.py tests/test_native_commerce.py tests/test_appverni.py
```

Qt-тесты требуют PySide6, для безэкранной проверки:
`QT_QPA_PLATFORM=offscreen`. Проверяются формы, роли, исходное поле 2FA,
проверка полной истории, кэш, передача App Store ID в исходный движок,
бесплатный резерв, блокировка платных заказов и восстановление после сбоя.
Физическая установка и настоящий Apple-вход требуют отдельной проверки
на Mac/Windows с устройством.
