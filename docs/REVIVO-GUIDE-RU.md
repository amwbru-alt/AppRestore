# ReVivo: руководство владельца и разработчика

## 1. Что это за проект

ReVivo («возвращаю к жизни») — бесплатная настольная утилита восстановления iOS-приложений.
Она работает на компьютере с подключённым по USB iPhone/iPad. Это форк AppRestore,
а не веб-сервис. Сервер приложений, база клиентов, подписки и платёжная система отсутствуют.

Основной сценарий — **восстановление из покупок Apple ID**:

1. При запуске открывается раздел «Покупки Apple ID». Войдите в тот аккаунт App Store,
   с которого раньше скачивали приложения. Для просмотра телефон не требуется.
2. Список загружается из истории аккаунта через `ipatool list-purchases --all`,
   а не из перечня установленных приложений телефона. В него входят и доступные
   покупки с прежних устройств. Бесплатные приложения, полученные этим Apple ID,
   также относятся к истории покупок.
3. В заголовке указан текущий Apple ID. Кнопка «Обновить» повторно запрашивает
   историю у Apple. При сетевой ошибке показывается ошибка, а не утверждение,
   что у аккаунта нет покупок. Кэш аккаунта отображается на время обновления.
4. Найдите приложение по названию и подключите iPhone/iPad, разблокируйте его,
   подтвердите «Доверять компьютеру». Нажмите «Восстановить» у нужной покупки.
   До подключения устройства список доступен для просмотра, установка отключена.
5. Доступность повторной загрузки определяет Apple. Список включает записи,
   возвращённые Apple для этого аккаунта; удаление из магазина, скрытые покупки,
   другой Apple ID и ограничения Apple могут влиять на доступность приложения.
6. Для отдельных сценариев со сгруженными приложениями закройте список и выберите
   «Приложения на телефоне». Вернуться можно через «Покупки Apple ID».

Новые платные покупки запрещены. Для установки собственных IPA используйте
«Файлы IPA»; исходный IPA должен соответствовать приложению и правам аккаунта.

Также доступны поиск по App Store и встроенному списку удалённых приложений,
журнал операций, диагностика и работа с IPA. Отсутствие приложения в магазине
не означает, что его можно восстановить с любым Apple ID. Исходный IPA должен
соответствовать приложению и доступным аккаунту правам.

## 2. Устройство кода

| Часть | Назначение |
| --- | --- |
| `apprestore_core/service.py`, `tools.py` | Сценарии восстановления и запуск инструментов |
| `apprestore_core/cli.py` | Консольные команды; `revivo --help` |
| `apprestore_core/ipa.py`, `ipa_index.py` | Чтение метаданных и индекс собственной библиотеки IPA |
| `apprestore_core/catalog.py`, `region_probe.py` | Каталог Apple, цены, проверка витрины аккаунта |
| `apprestore_core/ipatool_api.py` | Контракт с ipatool, ошибки, история приобретений |
| `apprestore_core/license_gate.py`, `license_guard.py`, `license_journal.py` | Согласие, цена, квоты, межпроцессная блокировка и локальный журнал |
| `apprestore_core/network_policy.py` | Разрешённые HTTP-направления Python и контроль редиректов |
| `apprestore_gui/ui4b/`, `qml4b/` | Основной интерфейс Qt Quick и его контроллеры |
| `apprestore_gui/theme.py`, `qml4b/theme/Theme.qml` | Тёмная тема виджетов и основного QML-интерфейса |
| `apprestore_gui/quick_session.py`, `auth_pty.py` | Сессия и интерактивная авторизация Apple ID |
| `apprestore_gui/account_vault.py`, `account_bindings.py` | Локальное хранение сессий и соответствий устройство → Apple ID |
| `apprestore_gui/updater.py` | Обновление из релизов вашего GitHub-форка с SHA-256 |
| `packaging/` | PyInstaller, сборка патченного ipatool, проверка и упаковка GUI |
| `.github/workflows/gui-build.yml` | Отдельные сборки на Windows и macOS |
| `tests/` | Автоматические проверки ядра, GUI, упаковки, сети и лицензий |

`pymobiledevice3` общается с устройством; отдельный Go-бинарник `ipatool`
входит в Apple ID и работает с App Store. Внутренние имена `apprestore_core`,
`apprestore_gui`, идентификатор Python-дистрибутива `apprestore`, команды совместимости
и старые переменные окружения сохранены. Публичное имя интерфейса и GUI-сборок — ReVivo.

## 3. Как попасть в админку

Админки **нет**: отсутствуют веб-сервер, маршрут `/admin`, отдельный аккаунт
владельца, пароль администратора и серверная база пользователей. Раздел «Apple ID»
в приложении — это вход в Apple, а не административная панель.

Владелец управляет проектом через исходники и GitHub: вкладки Code, Pull requests,
Actions и Releases. Настройки пользователя находятся в самом приложении.
Для бесплатного использования не требуется выдавать тариф или менять запись в БД.

## 4. Как включить безлимит себе

Бесплатность приложения уже включена для всех. Локальный защитный счётчик новых
бесплатных лицензий по умолчанию оставлен: **5 за 24 часа, 15 за всё время**.
Повторное скачивание уже купленного и восстановление сгруженного в эту квоту не входят.
Это не платная подписка и не лимит Apple.

В этом форке есть явный локальный режим владельца `REVIVO_UNLIMITED_LICENSES=1`.
Он снимает только эти две квоты, сохраняя журнал, блокировки, согласие, проверку
цены и запрет новых платных покупок. Переменная применяется при запуске; закройте
все экземпляры приложения перед включением/выключением.

**Windows PowerShell, готовая сборка:**

```powershell
$env:REVIVO_UNLIMITED_LICENSES = '1'
& '.\ReVivo\ReVivo.exe'
```

**macOS, готовая сборка:**

```bash
REVIVO_UNLIMITED_LICENSES=1 ./ReVivo.app/Contents/MacOS/ReVivo
```

**Из исходников, PowerShell:**

```powershell
$env:REVIVO_UNLIMITED_LICENSES = '1'
python -m apprestore_gui --ui quick
```

**Из исходников, macOS:**

```bash
REVIVO_UNLIMITED_LICENSES=1 python -m apprestore_gui --ui quick
```

В окне согласия появится «Локальный лимит отключён владельцем».
Чтобы вернуть квоты, закройте приложение и запустите без этой переменной.
В PowerShell удалите её: `Remove-Item Env:REVIVO_UNLIMITED_LICENSES`.

Режим действует на **все Apple ID в запущенном процессе**, а не на один аккаунт.
Он не предоставляет прав на чужие приложения, не снимает ограничения Apple,
не меняет регион и не позволяет бесплатно получить платное приложение.
Никакой серверной записи о выданном «безлимите» нет.

## 5. Данные и локальные файлы

- `~/.ipatool` — активная сессия ipatool (содержимое чувствительное).
- `~/.apprestore/keychains` — локальные копии зашифрованных сессий аккаунтов;
  имя папки и `active.txt` могут содержать email.
- `~/.apprestore/device-accounts.json` — локальная привязка UDID к email.
- `~/.apprestore/licenses_acquired.jsonl` — журнал новых лицензий без паролей,
  токенов, Apple ID и UDID; включает идентификаторы приложений, время и результат.
- `APPRESTORE_LICENSE_JOURNAL` может переопределить путь журнала.
- На macOS библиотека IPA: `~/Library/Application Support/ReVivo/ipas`.
- На Windows библиотека IPA: `~/ReVivo/ipas`.
- `APPRESTORE_IPA_DIR`, `APPRESTORE_CACHE_DIR`, `APPRESTORE_DATA_DIR` позволяют
  явно задать свои каталоги. QSettings использует организацию/приложение ReVivo.

При переходе с AppRestore новое имя меняет стандартные каталоги библиотеки,
кэша и QSettings. Старые IPA автоматически не перемещаются: выберите старую папку
через `APPRESTORE_IPA_DIR` либо перенесите файлы вручную. Сессии и журнал в
`~/.apprestore` сохраняют прежние пути. Перед переносом сделайте резервную копию.

Сетевые направления и ограничения проверки описаны в отдельном
[отчёте](REVIVO-NETWORK-AUDIT-RU.md).

## 6. Подготовка окружения и запуск

Рекомендуется Python **3.12**, поддерживаются 3.10–3.13. Для сборки ipatool нужен
**Go 1.25.0**, Git, Git Bash на Windows / bash на macOS и C-инструменты для Go/cgo
там, где они требуются. На macOS установите Xcode Command Line Tools (`xcode-select --install`).
На Windows установите Apple Devices либо компоненты Apple Mobile Device и драйверы USB.

```bash
git clone https://github.com/amwbru-alt/AppRestore.git
cd AppRestore
python -m venv .venv
```

Активация:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# macOS
source .venv/bin/activate
```

```bash
python -m pip install -e '.[gui]' -r requirements/gui-build.txt
```

В PowerShell одинарные кавычки вокруг `.[gui]` тоже допустимы.
Зависимости сборки GUI закреплены в `requirements/gui-build.txt`;
хэшированные наборы CLI — в `requirements/`. Не заменяйте закреплённый ipatool
случайным опубликованным бинарником.

### Сборка и установка ipatool

На macOS проще использовать:

```bash
bash packaging/bootstrap-ipatool.sh
```

Скрипт при необходимости загружает закреплённый Go, собирает ipatool с патчами
и устанавливает в `bin/ipatool`. Для Windows откройте Git Bash в корне проекта:

```bash
bash packaging/build-ipatool.sh windows-amd64
```

Архив появится в `dist/ipatool/ipatool-2.6.0-windows-amd64.tar.gz`.
Для запуска из исходников распакуйте **свой собранный** архив в `bin`:

```bash
mkdir -p bin
tar -xzf dist/ipatool/ipatool-2.6.0-windows-amd64.tar.gz -C bin
```

Внутри архива ожидается `ipatool.exe`. Проверьте: `bin/ipatool.exe --version`.
На macOS соответствующие цели — `macos-arm64` или `macos-amd64`;
их можно передать напрямую в `packaging/build-ipatool.sh`.

```bash
python -m apprestore_gui --ui quick
# альтернативные команды после установки:
revivo-gui
revivo --help
```

Сборка ipatool загружает исходники `majd/ipatool`, Go и Go-зависимости.
Это обращения процесса сборки, а не отправка данных пользователя приложения.
Патчи и контрольные суммы описаны в `packaging/BUILD-ipatool.md`.

## 7. Компиляция готового приложения

PyInstaller собирает приложение **на целевой ОС**. Windows EXE собирайте на
Windows, macOS `.app` — на macOS. Здесь не используется кросс-компиляция GUI.

После установки Python-зависимостей:

```bash
pyinstaller packaging/apprestore-gui.spec --noconfirm --clean
```

### Windows

В Git Bash соберите ipatool, если ещё не собрали:

```bash
bash packaging/build-ipatool.sh windows-amd64
```

В активированном Python-окружении:

```bash
python packaging/package_gui.py --out gui-dist --expect-version 0.4.0 --ipatool-archive dist/ipatool/ipatool-2.6.0-windows-amd64.tar.gz
```

Результат: `gui-dist/ReVivo-GUI-Windows.zip`, контрольная сумма и self-test JSON.
В ZIP — папка `ReVivo`, запуск `ReVivo.exe`. Распространяйте папку целиком,
а не один EXE.

### macOS

Apple Silicon:

```bash
bash packaging/build-ipatool.sh macos-arm64
python packaging/package_gui.py --out gui-dist --expect-version 0.4.0 --ipatool-archive dist/ipatool/ipatool-2.6.0-macos-arm64.tar.gz
```

Для Intel замените `macos-arm64` на `macos-amd64`.
Результат: `gui-dist/ReVivo-GUI-macOS.zip` с `ReVivo.app` и
`gui-dist/ReVivo-macOS.dmg` для установки перетаскиванием в Программы.
Упаковщик выполняет ad-hoc подпись, self-test и проверку распакованного приложения.
Developer ID/notarization не подключены: создание DMG не требует ключей Apple,
но формат DMG не убирает предупреждение Gatekeeper. При первом запуске может
потребоваться разрешение в Конфиденциальность и безопасность → Всё равно открыть.
Подробнее: [установка DMG и ограничения Gatekeeper](REVIVO-MACOS-DMG-RU.md).

### GitHub Actions

После попадания изменений в нужную ветку откройте репозиторий → **Actions → GUI build → Run workflow**,
выберите ветку с ReVivo и запустите. Workflow собирает Windows и macOS;
после успешного завершения скачайте артефакты `ReVivo-GUI-Windows` и `ReVivo-GUI-macOS`.
Для публикации релиза используйте существующий release workflow после проверки
версии и исходников. Наличие готовых релизов форка необходимо для автообновления.
Пока релизов нет, проверка обновления может сообщать об ошибке/отсутствии релиза.
Старые CLI-инсталляторы требуют отдельно опубликованных закреплённых архивов ipatool
в вашем форке; основной рекомендуемый путь — новая GUI-сборка, не старые one-liner установщики.

## 8. Проверка перед распространением

```bash
python -m compileall -q apprestore_core apprestore_gui
python -m pytest -q
```

Для тестов GUI без монитора: macOS/Linux — `QT_QPA_PLATFORM=offscreen python -m pytest -q`;
PowerShell — `$env:QT_QPA_PLATFORM='offscreen'`, затем `python -m pytest -q`.
Снимки интерфейса без Apple ID и сети:

```bash
python scripts/ui4b_screenshots.py --out build/revivo-preview --only home-missing
```

Дополнительно на реальных Windows/macOS проверьте USB, доверие к компьютеру,
авторизацию и 2FA своим Apple ID, повторное скачивание своего приложения,
восстановление собственного IPA и выход из аккаунта. Автотесты с подставными
ответами не подтверждают работоспособность конкретного аккаунта или доступность
конкретного приложения на серверах Apple.

## 9. Бесплатность и дальнейшие изменения

В ReVivo нет оплаты, подписки, реквизитов получателя и платёжных webhook.
Ни владельцу, ни пользователям не нужно платить за доступ к этой программе.
Покупки, сделанные пользователем отдельно в App Store, принадлежат экосистеме Apple.

Для собственного сервера в будущем сначала нужны назначение, API, домен и
серверный код. Перенаправление Apple ID/паролей на ваш сервер не реализовано:
приложение продолжает использовать прямой вход Apple. Если понадобится платный
сервис, это отдельная разработка backend/биллинга, а не замена найденных реквизитов.
