# Каталог приложений и иконок AppRevive

Приложение получает каталог через `http://IP:3000/v1/catalog`.
Реквизиты MySQL находятся только на Node.js-сервере в `.env`.
[Запуск API и настройка адреса приложения](server/node/README.md).

## Создание и наполнение

В терминале подключитесь к MySQL, как прежде. В `mysql>`:

```sql
USE apple;
source /Users/macbook/Downloads/AppRestore-codex-apprevive-icons/server/promo/catalog-schema.sql;
source /Users/macbook/Downloads/AppRestore-codex-apprevive-icons/server/promo/catalog-seed.sql;
SELECT COUNT(*) FROM apprevive_app_catalog;
exit;
```

Первый импорт добавит 670 приложений. Повторный импорт сохраняет изменения администратора. Таблицы кодов и баланс не затрагиваются.

| Поле | Что хранится |
| --- | --- |
| store_id | ID App Store, уникальный |
| name | Название в списке |
| icon_url | HTTPS-адрес картинки, пустой — искать у Apple |
| enabled | 1 — показывать, 0 — скрыть из каталога |
| updated_at | Время изменения |

Приложение читает каталог из Node.js API в фоне. Каталог используется
только для названий и картинок. Он **не добавляет** приложения в список
восстановления и не подтверждает владение.

После входа в Apple ID открывается список «Удалённые из App Store»:
берётся история этого аккаунта, затем доступность проверяется публичным
Apple Lookup в витрине аккаунта и фиксированных контрольных витринах RU/US.
Показываются только строки со статусом DELISTED. Доступные, только
регионально недоступные и непроверенные приложения не попадают в список.
Это не доказательство удаления во всех странах и не гарантия загрузки.
Скрытые или не возвращённые Apple элементы истории нельзя обещать обнаружить.

Полностью установленные приложения исключаются по данным подключённого
телефона; сгруженные остаются кандидатами. Сам список установленных на
главном экране не отображается. Данные устройства всё ещё читаются внутри
приложения для проверки установки и свободного места.

Сетевые ошибки не считаются удалением. «Обновить» повторяет загрузку и
проверку. При смене Apple ID результаты старого аккаунта очищаются, поздние
ответы не принимаются. История Apple ID не отправляется в наш Node.js API:
сервер отдаёт общий каталог, а сопоставление выполняется локально.

## Автоматически найти картинки

На Node.js-сервере, после установки зависимостей, из папки `server/node`:

```bash
npm run sync-icons
```

Команда проверяет Apple Lookup в регионах RU и US и записывает найденные HTTPS-адреса в базу. Заданные вручную картинки не перезаписываются. Повторный запуск обрабатывает оставшиеся пустые адреса. Для удалённых приложений Apple может не вернуть картинку.

## Добавить своё приложение и картинку

Загрузите PNG/JPEG на свой HTTPS-сайт (например, `https://sv-bz.ru/uploads/icons/`). Затем:

```sql
INSERT INTO apprevive_app_catalog (store_id, name, icon_url)
VALUES ('492224193', 'Сбербанк Онлайн', 'https://sv-bz.ru/uploads/icons/sber.png')
ON DUPLICATE KEY UPDATE name=VALUES(name), icon_url=VALUES(icon_url), enabled=1;
```

Адрес в примере нужно заменить на реально загруженный файл. В MySQL хранится адрес; сама картинка хранится на сайте и кешируется на компьютере пользователя. Так база не передаёт сотни изображений при каждом открытии.

Если ID уже есть в истории покупок, сохраняется название из истории, но картинка каталога применяется к этой же строке.

Скрыть приложение из стандартного каталога (историю покупок это не удаляет):

```sql
UPDATE apprevive_app_catalog SET enabled=0 WHERE store_id='492224193';
```

Порядок картинки: заданный в каталоге URL → Apple RU/US → известная иконка сайта → встроенная нейтральная иконка восстановления. Неудачная картинка не мешает установке. Для видимых приложений без найденного изображения есть стандартная SVG-картинка внутри приложения, доступная без интернета.

Доступ к MySQL у пользователей приложения отсутствует. Каталог редактирует
администратор в базе или серверными CLI-командами. Рабочий API отдаёт только
публичные названия, ID и адреса картинок, но не реквизиты подключения.
